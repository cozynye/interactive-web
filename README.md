# web-playground

화면에서 움직이는 효과를 경로별로 하나씩 모아 두는 Next.js 사이트다. 홈에는 효과마다 타일이 하나씩 있고, 타일의 버튼을 누르면 해당 경로로 이동한다.

## 들어 있는 것

| 경로 | 내용 |
|---|---|
| `/` | 효과 목록. 타일 배경에서 미리보기가 돈다. |
| `/fire` | 뜨개질 코 모양으로 그리는 불꽃놀이 |
| `/ascii` | 아스키 작품 목록 |
| `/ascii/<이름>` | 아스키 작품 하나를 전체 화면으로 |
| `/game` | 글자로 그리는 생존 게임 「글자 평원의 용」 |

### 불꽃놀이

하늘을 클릭하거나 터치하면 그 자리로 폭죽이 올라가서 터지고, 땅을 누른 뒤 글자를 쓰고 엔터를 치면 글자 모양으로 터진다. 글자는 40자까지 쓸 수 있고 "링크 복사"를 누르면 `?text=` 가 붙은 주소가 복사되어 그 주소를 연 사람 화면에서 같은 글자가 터진다. 상단 막대에서 실 색 19가지와 하늘 색 7가지를 고르고, 슬라이더로 자동으로 올라가는 폭죽의 양을 0에서 10 사이로 조절한다. 고른 값은 브라우저 `localStorage`에 남아서 다시 열어도 유지된다.

라이브러리 없이 Canvas 2D로 직접 그리며, 가로 7px 세로 6px짜리 코 격자에 입자를 찍는 방식이라 동시에 떠 있는 입자는 4,000개로 제한한다. 소리는 Web Audio로 합성하는데 브라우저 정책상 첫 클릭 이후에만 난다.

도넛을 뺀 12개는 같은 무대(`src/features/ascii/stage/AsciiStage.tsx`)에서 돈다. 장면이 매 프레임 글자 격자에 밝기와 색, 글자를 써 넣으면 무대가 Canvas에 칸 단위로 글자를 그리고, 같은 그림을 흐리게 한 겹 더 깔아서 빛이 번지게 한다. 칸 폭은 기본 6px(남산은 5px)이고 화면 폭에 따라 가로 56칸에서 200칸(남산은 240칸) 사이로 격자를 잡아 초당 30장을 그린다. 3D 장면은 점 구름을 투영해서 칸마다 가장 가까운 점을 남기고 밝기로 `.,:;-~=+*xo%#@` 중 한 글자를 고른다. 장미처럼 덩어리로 보여야 하는 물체는 점마다 조각 번호를 달아 두고, 빈 곳이나 더 뒤에 있는 다른 조각과 맞닿은 칸에 방향에 맞는 선 글자(`| / \ - _`)로 윤곽을 긋는다. 안쪽 칸은 밝기 4단계마다 정해 둔 글자 묶음에서 고르고 초당 3번 다른 글자로 바뀐다. 블랙홀은 점을 쓰지 않고 칸마다 그 자리 가스의 온도를 계산해서 글자와 색을 정한다. 무대는 앞 프레임을 45% 남겨 잔상을 만들고, 좁게 흐린 겹과 넓게 흐린 겹을 하나씩 얹어 빛이 번지게 한다. 색은 장면마다 두세 가지로 제한했고 블랙홀만 온도에 따라 붉은색에서 금색까지 5단계를 쓴다.

점 구름을 글자 칸으로 옮기는 방식, 조각 경계의 윤곽선, 밝기별 글자 묶음, 빛살, 잔상과 번짐은 JIN2(@jin_22ee)의 Python 아스키 작품들(github.com/JIN2-ASCII/-JIN2-ASCII)에서 배운 기법이다. 블랙홀 장면은 그중 BLACK HOLE의 구성(그림자, 휘어 보이는 고리, 안쪽이 빨리 도는 원반)과 계산 방식을 따라 TypeScript로 다시 짠 것이다. 도입 순서(원, 빛, 원반, 번쩍임)도 원작을 따랐으며 원작의 저작권은 JIN2에게 있다.

기사 장면은 다른 장면과 달리 입체 모형을 쓴다. 눈구멍이 가로로 난 통투구, 사슬 옷, 붉은 십자가 그려진 겉옷, 어깨판, 장갑, 무릎 가리개와 정강이 판, 망토, 허리의 검, 손막이가 달린 창, 바위에 기대 놓은 연 모양 방패를 거리 함수 덩어리로 빚어 두고 220 × 182 크기로 훑어서(레이마칭) 밝기와 그림자, 재질, 깊이를 구워 둔 뒤, 매 프레임에는 그 그림을 4px 칸으로 읽어 글자로 옮긴다. 굽는 데 1초 넘게 걸려서 한 프레임에 7ms씩 위에서부터 나눠 굽고, 기사가 위에서 아래로 드러나는 동안 굽는 줄이 앞서간다. 글자는 밝기 하나로 고르지 않는다. 재질마다 글자 묶음이 달라서 쇠는 기호(`.:-=+*%#@`), 천은 세로로 선 글자, 사슬은 한 칸 건너 엇갈리는 둥근 글자로 채우고 밝기는 색이 맡는다. 옆 칸이 비었거나 깊이가 0.06 넘게 뒤에 있는 칸은 가장자리로 보고 선이 달리는 방향에 맞춰 `| _ - / \`를 밝게 그어서 팔과 몸통, 판과 판이 선으로 갈라진다. 가장자리를 방향 글자로 긋는 것은 Acerola의 아스키 셰이더에서, 글자가 형태를 맡고 색이 밝기를 맡게 나누는 것은 ArdaaaU/ascii-knight에서 가져온 생각이다. Alex Harri의 글에 나온, 칸을 여섯 구역으로 나눠 모양이 닮은 글자를 찾는 방식은 적용하지 않았다. 자세는 앉음에서 섬까지 7장을 구워 두고 일어서거나 앉는 2.4초 동안 이웃한 두 장을 칸 덩어리(3 × 2칸) 단위로 섞어 가며 넘기는데, 가운데 5장은 잠깐만 보여서 가로세로 절반 크기로 굽는다. 아직 덜 구운 장은 가장 가까운 다 구운 장으로 대신한다. 윗몸은 엉덩이를 축으로 통째로 옮기고 숙이며, 무릎과 팔꿈치는 양 끝 마디의 자리에서 계산한다. 몸이 실제로 이어서 움직이는 것은 아니어서 넘어가는 동안 윤곽이 덩어리째 바뀌는 것이 보인다. 깃발은 천을 시뮬레이션한 것이 아니고 물결 두 개를 겹친 곡선에 폭과 음영을 입힌 것이다. 구도와 날리는 천의 표현은 인스타그램에 올라온 아스키 기사 영상들과 ArdaaaU/ascii-knight의 방식을 참고했고 코드는 가져오지 않았다. 카피바라와 귤, 유자, 그리고 게임의 용은 모형을 굽지 않고 매 프레임 높이 함수를 계산한다. 둥근 덩어리들의 높이를 겹친 뒤 옆 칸과의 높이 차이로 면이 받는 빛을 구해서 글자와 색을 고르는 방식이고(`stage/relief.ts`), 덩어리가 만나는 자리에는 골이 저절로 진다. 마법진과 카피바라, 남산의 건물도 같은 곳에서 본 영상(@lilian.chiuuu, @dwcminh.ascii, @ai.asap.kr)의 구성을 참고해 새로 짰다.

제드 장면은 중계 화면을 옮긴 것이 아니고 알려진 순서에 맞춰 위치와 시간을 새로 짠 것이라 실제 경기와 초 단위로 맞지 않는다. 캐릭터 모습은 제드 인게임 모델 그림을 글자 칸 80 × 42로 줄여서 쓴다. 이 장면은 Riot Games의 "Legal Jibber Jabber" 정책에 따라 Riot Games 소유의 자산을 사용해 만들었고, Riot Games는 이 프로젝트를 보증하거나 후원하지 않는다.

### 아스키 게임

`/game`은 글자 격자에 그리는 탑다운 생존 게임이고 뱀파이어 서바이버즈의 구조를 따른다. 끝이 없는 벌판에서 화면 밖에서 몰려오는 무리를 상대하는데, 공격은 저절로 나가고 플레이어는 움직임과 구르기만 조작한다. 쓰러진 적이 떨군 구슬을 모으면 단계가 오르고(필요한 경험치는 5, 11, 17처럼 6씩 늘어난다), 그때마다 싸움이 멈추고 무기나 능력 셋 중 하나를 고른다. 3분이 되면 체력 8,000인 용이 나타나고 용을 쓰러뜨리면 끝난다.

무기는 검(가까운 적 쪽으로 베기), 검기(가까운 적에게 날아가 꿰뚫음), 도는 칼날, 낙뢰(아무 적에게나 떨어짐), 룬의 고리(둘레에 계속 피해) 5가지이고 능력은 힘, 신속, 장화, 자석, 심장 5가지이며 모두 5단계까지 오른다. 적은 구울, 박쥐, 해골, 돌거인 4종이고 시간이 갈수록 단단한 종류가 섞인다. 화면에 있어야 할 적의 수는 시간의 제곱에 비례해 12마리에서 220마리까지 늘고, 40초마다 박쥐 떼가 한쪽에서 몰려오며, 1분마다 나오는 우두머리는 열면 바로 하나를 올려 주는 상자를 떨군다. 용의 공격은 바닥에 붉은 범위로 먼저 깔려서 안쪽부터 차오르고 다 찬 순간에 한 번 판정한다. 범위는 부채꼴(숨결), 원(꼬리치기, 떨어지는 불덩이), 직선(돌진) 세 가지로 시작하고, 용의 체력이 반이 되면 포효한 뒤 예고 시간이 18% 짧아지며 고리와 십자 범위가 추가된다. 용의 공격에는 무리도 함께 휩쓸린다.

| 입력 | 동작 |
|---|---|
| WASD, 방향키 | 이동 |
| Space, 왼쪽 Shift | 구르기 (0.3초 무적) |
| 1, 2, 3 | 단계가 올랐을 때 고르기. 카드를 눌러도 된다. |
| Enter | 시작, 다시 하기 |

터치 기기에서는 화면 어디든 손가락을 대면 조이스틱이 되고 오른쪽 아래에 구르기 버튼이 나온다. 게임 규칙은 화면과 분리된 `src/features/game/engine.ts`에 있어서 테스트가 화면 없이 돌리고, 홈 타일의 미리보기도 같은 엔진을 간단한 규칙(`bot.ts`)으로 조종해서 보여 준다. 화면은 (글자, 색) 조합을 한 번만 그려 두고 복사하는 방식으로 그리고, 세 겹으로 나뉜다. 풀과 용과 무기 효과는 글자 칸에 맞춰 그린 뒤 카메라가 칸에서 벗어난 만큼 통째로 밀어서 놓고, 주인공과 무리와 구슬은 칸에 맞추지 않은 제자리에 얹으며, 체력과 경험치 같은 글자판은 화면에 붙박아 둔다. 그래서 걸을 때 화면이 한 칸씩 튀지 않고 흐른다. 규칙은 화면이 한 장 그릴 때마다 그 사이에 흐른 시간만큼 진행하고, 한 번에 1/60초를 넘기지 않도록 나눈다. 주인공은 껍질에 싸인 글자 `@`이고 가로 7칸, 세로 3줄이며, 껍질 무늬 2장을 번갈아 바꾸고 둘레에 불티 둘이 돈다.

경험치 곡선, 선택지 3개, 화면 밖에서 나타나는 방식, 있어야 할 적의 수를 채우는 방식은 뱀파이어 서바이버즈 위키(vampire.survivors.wiki)의 수치에서 가져와 3분짜리로 줄였다. 적의 수를 시간의 제곱으로 늘리는 것은 brac/swarmr에서, 걷는 쪽에서 적이 더 자주 나오게 하는 것은 matthiasbroske/VampireSurvivorsClone에서, 여러 줄 글자 그림으로 주인공과 적을 그리는 방식은 ascii-art.de의 기사 그림과 Stone Story RPG에서 참고했고 코드는 가져오지 않았다. 화면 구성은 @ansenjeo와 @ztryfu가 공개한 아스키 게임 영상을 참고했다. 서버가 없는 혼자 하는 게임이고 맵은 하나, 용은 한 마리이며 기록은 저장하지 않는다. 난이도는 자동 조종으로 돌려 본 결과에 맞춘 것이라 사람이 하면 다르게 느껴질 수 있다.

## 실행

Node.js 20.9 이상과 pnpm이 필요하다.

```
pnpm install
pnpm dev
```

`http://localhost:3939`에서 열린다. 배포용 빌드는 `pnpm build` 후 `pnpm start`로 확인한다. 고친 뒤에는 `pnpm check`가 린트, 타입 검사, 테스트를 한 번에 돌린다.

## 구조

```
src/
├── app/           경로별 페이지
├── components/    공통 내비게이션, 홈 타일용 미리보기
└── features/
    ├── fire/      불꽃놀이 엔진(knitFireEngine.ts)과 화면
    ├── ascii/     아스키 작품과 목록(asciiList.ts)
    └── game/      생존 게임 규칙(engine.ts), 그리기(draw.ts), 입력(controls.ts), 자동 조종(bot.ts), 글자 판 렌더러(ink.ts), 화면(GameStage.tsx)
```

아스키 작품을 추가할 때는 `src/features/ascii/asciiList.ts`에 항목을 넣고 `src/app/ascii/<slug>/page.tsx`를 만든다.

## 한계

홈 타일의 불꽃 미리보기는 본편 엔진을 축소한 것이 아니라 따로 짠 간단한 버전이라 모양 불꽃이나 글자 불꽃은 나오지 않는다. 아스키 장면은 글자를 칸마다 `fillText`로 그리기 때문에 목록 페이지처럼 여러 장면이 한 화면에 동시에 보이면 저사양 기기에서 프레임이 떨어질 수 있다. 자동 테스트는 아스키 장면과 재생 상태 판정, 게임 규칙만 다루고(`pnpm test`), 불꽃놀이 엔진은 테스트가 없다. 동작은 데스크톱 Chrome에서만 확인했고, 게임의 터치 조작은 실제 기기에서 확인하지 못했다. 게임은 난이도 조절이 없고 기록이 저장되지 않는다.
