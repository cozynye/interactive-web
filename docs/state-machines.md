# 상태머신 지도

이 앱에서 "지금 어떤 상태인가"를 가지고 있는 곳을 전부 모은 문서다. 명시적으로 고친 것과 일부러 그대로 둔 것을 나눠 적었고, 그대로 둔 것은 어떤 변수가 상태 노릇을 하는지 적어 두었다. 상태를 건드리는 코드를 고치기 전에 여기서 해당 항목을 먼저 확인한다.

## 명시적으로 만든 것

### 애니메이션 재생 상태 (`src/lib/runState.ts`, `src/lib/ticker.ts`)

홈의 불꽃 미리보기, 아스키 무대, 도넛이 모두 같은 상태머신을 쓴다.

```
입력: reducedMotion, onscreen, pageVisible

still    움직임 줄이기가 켜져 있다. 정지 장면 한 장만 그린다.
paused   화면 밖이거나 탭이 가려졌다. 시간도 흐르지 않는다.
playing  그리는 중.

reducedMotion        → still
!onscreen 또는 !pageVisible → paused
그 밖                 → playing
```

상태는 입력 세 개로만 정해지고(`runStateOf`), `createTicker`가 입력을 지켜보다가 루프를 켜고 끈다. 지금 상태는 해당 요소의 `data-state` 속성에 적힌다. 전에는 컴포넌트 세 개가 `raf`, `visible`, `still` 변수로 같은 일을 각자 했고, 움직임 줄이기 설정은 처음 한 번만 읽었으며, 도넛은 화면 밖에서도 루프가 돌았다.

### 불꽃놀이 화면 (`src/features/fire/FirePage.tsx`)

| 상태 | 값 | 바깥에서 읽는 곳 |
|---|---|---|
| 열린 패널 | `yarn` / `sky` / 없음 | `.fire-page[data-panel]` |
| 땅 글씨 | 있음 / 없음 (쏘아 올리기 버튼이 보이는 조건) | `.fire-page[data-ground]` |
| 안내 문구 | 보임 → 사라짐 (되돌아가지 않는다) | `.fire-page[data-hint]` |
| 토스트 | 숨김 → 보임 → 숨김 | `useToast` 훅, `.toast.on` |

토스트는 `useToast`가 타이머 하나로 관리한다. 보이는 중에 다시 띄우면 시간을 처음부터 다시 센다.

### 장미의 한 주기 (`src/features/ascii/stage/rose.ts`)

`grow`(0~2.4초) → `bloom`(2.4~10.4초) → `full` → `fade`(마지막 1.4초) 순서로 28초마다 되풀이한다. 경계는 파일 위쪽 상수에 있고 `rosePhase()`가 이름을 돌려준다.

### 블랙홀의 도입 (`src/features/ascii/stage/blackhole.ts`)

`ring`(0~2.2초, 원이 한 바퀴 그려진다) → `glow`(2.2~5초, 붉은 빛이 차오른다) → `disk`(5~7.8초, 원반이 옆으로 퍼진다) → `flow`(7.8초 이후, 번쩍인 뒤 계속 흐른다) 순서로 한 번만 지나가고 되돌아가지 않는다. 경계는 파일 위쪽 상수에 있고 `blackholePhase()`가 이름을 돌려주며 화면 왼쪽 위에도 표시된다. `flow`에 들어간 뒤의 번쩍임은 `flareAt`(다음 번쩍임 시각)과 `lastFlare`로 정해지고, 간격은 9~18초 사이에서 매번 새로 뽑는다.

### 제드 맞대결의 한 편 (`src/features/ascii/stage/zed.ts`)

`push`(0~3초, 포탑에 맞으며 물러난다) → `mark`(3~4.5초, 점화와 두 사람의 표식) → `trade`(4.5~7.8초, 정화, 그림자 바꾸기, 표창) → `chase`(7.8~8.8초, 점멸과 마무리) → `after` 순서로 18초마다 되풀이한다. 사건 시각은 파일 위쪽 `AT`에 모여 있고 `zedPhase()`가 이름을 돌려준다. 위치는 `FAKER`·`RYU`, 체력은 `FAKER_HP`·`RYU_HP`, 왼쪽 위 기록은 `LOG` 표에 있으며 모두 시각만으로 정해져서 따로 기억하는 상태가 없다.

### 다른 장면의 도입

나머지 장면도 처음 한 번만 펼쳐지고 되돌아가지 않는다. 따로 상태 변수를 두지 않고 시각 `t`와 파일 위쪽의 상수만으로 정해지므로, 순서를 바꿀 때는 그 상수를 고친다.

| 장면 | 순서 | 상수 |
|---|---|---|
| 남산 | 산이 드러남 → 건물이 가장자리부터 솟음(1.2초~) → 타워가 아래에서 위로(1.8~5.4초) → 창에 불(3.6초~) → 전망대 불(5.7초) → 경광등(6.6초) → 첫 불꽃(7.3초) | `TOWER`, `LIGHT_AT`, `BEACON_AT`, `FIRST_SHOT`, 건물과 창은 식 안에 있다 |
| 마법진 | `drop`(0~1초) → `circle`(1~4.9초) → `rise`(~8.2초) → `hover`. `sigilPhase()`가 이름을 돌려준다 | `DROP`, `CIRCLE_END`, `RISE`, 도형별 시각은 `rings`와 `poly()` 호출에 있다 |
| 기사 | `ground`(0~1.2초) → `body`(~4.6초) → `glint`(~5.6초) → `wind`. `knightPhase()`가 이름을 돌려준다 | `BODY`, `GLINT_AT`, `WIND_AT` |
| 기사의 자세 | `sit` → `rising`(2.4초) → `stand` → `sitting`(2.4초) → `sit`. 12초에 처음 일어서고 30초마다 되풀이한다. `knightStance()`가 이름을 돌려준다 | `STAND_AT`, `CYCLE`, `RISE`, `SIT_AT`. 자세는 구워 둔 그림 7장(`POSES`) 가운데 이웃한 두 장을 덩어리 단위로 섞어 보여 준다 |
| 기사의 보는 틀 | 가까이(~4.6초) → 5초에 걸쳐 물러남 → 멀리. 앉아 있는 동안 주기의 18~28.5초에 한 번 4초에 걸쳐 다가갔다가 4초에 걸쳐 물러난다. 배율은 곱으로 바꾸고 가운데 점은 배율의 역수를 따라 옮겨서 화면의 한 점을 축으로 움직인다(`between()`) | `NEAR`, `WIDE`, `FACE`(배율과 가운데 점), `CLOSE`, `MOVE` |
| 카피바라 | 물 → 몸이 코끝부터(0.8~4초) → 첫 귤(4.6초) → 김(6초) → 유자 7개(6.4초~) → 눈(8.5초) | `DRAW`, `FIRST_ORANGE`, `STEAM_AT`, `YUZU_AT`, `SNOW_AT` |
| 트리 | 아래에서 위로 쌓임(4초) → 전구가 아래부터 켜짐(4.5초~) → 별과 빛살(6.2초) → 눈 | `BUILD`, `LIGHTS_AT`, `STAR_AT` |
| 은하 | 한 점(1.2초) → 별이 퍼지며 팔이 풀림(5.2초 동안) → 중심 번쩍임(6.6초) → 별똥별 | `BIRTH`, `SPREAD`, `FLASH` |
| 별이 빛나는 밤 | 달과 별이 켜짐 → 붓질이 번짐 → 사이프러스와 능선 → 마을 창 → 서명(8.5초~) | 상수 없이 식 안에 있다 |
| 강변 불꽃놀이 | 창과 강변 불빛(3초) → 첫 발 | `next`의 초깃값 |
| 별빛 | 빛이 차오름 → 번쩍이며 터짐(1.8초) | `BANG` |

장미는 주기마다 다 핀 뒤 이슬 네 방울이 `DROP_AT` 시각에 맺혀 `HANG`초 매달렸다가 떨어진다. 떨어지는 자리는 `drops[].at`에 담기고 주기가 새로 시작하면 비운다.

카피바라의 귤은 34초(`CYCLE`)마다 되풀이한다. `EVERY`(9초)마다 하나씩 3개까지 쌓이고, `WOBBLE`(21초)부터 고개가 좌우로 조금씩 흔들리다가 `DROPS`(24.5초, 25.8초, 27초)에 위의 귤부터 하나씩 굴러떨어진 뒤 쉰다. 모두 시각만으로 정해지고 `orangesOn()`이 지금 얹힌 수를 돌려준다.

### 게임 (`src/features/game/engine.ts`)

게임 상태는 `Game` 객체 하나에 있고 `update(game, input, dt)`만 고친다.

```
title → fight ⇄ levelup → won 또는 lost → (1.2초 뒤 시작 입력) → fight
```

화면은 지금 단계를 `main[data-phase]`에 적는다. `levelup`은 경험치가 차거나 상자를 열었을 때이고, 고를 때까지 싸움의 시간(`game.t`)이 흐르지 않는다. 선택지가 연달아 뜨면 단계 이름이 그대로라서 화면은 `game.offers`가 늘었는지도 함께 본다. 싸움 안에서 상태 노릇을 하는 값은 아래와 같다.

| 상태머신 | 상태 | 상태를 담은 변수 |
|---|---|---|
| 성장 | 경험치 모음 → 고르기(셋 중 하나) → 경험치 모음 | `player.xp`, `player.next`, `player.level`, `game.choices`, 무기와 능력의 단계 `player.lv` |
| 무기 | 기다림 → 발동 (무기마다 따로) | `player.cd[무기]`, 뒤쪽 베기 `player.backIn`, 칼날 각도 `player.orbit` |
| 무리 | 화면 밖에서 나타남 → 다가옴 → 쓰러져 구슬이 됨 | `game.spawn`(다음 적까지), `game.eliteAt`(다음 우두머리), `Enemy.hp`, 밀려나는 속도 `Enemy.kx`·`ky` |
| 구슬 | 놓임 → 끌려옴 → 주움 | `Gem.pulled`, `Gem.xp`(0은 고기, -1은 상자) |
| 용의 등장 | 없음 → 나타나 포효(`BOSS_AT` 180초) | `boss.here` |
| 용의 행동 | 쉼(다가오며 몸을 돌림) → 공격 준비 → 쉼 | `boss.wait`(다음 행동까지), `boss.casting`(공격 중 남은 시간), `boss.last`(직전 공격) |
| 용의 돌진 | 준비 → 달림 → 끝 | `boss.chargeIn`, `boss.charging`, `boss.tx`·`ty` |
| 용의 분노 | 평소 → 포효(1.6초, 피해 없음) → 분노 | `boss.enraged`, `boss.roar` |
| 공격 범위 | 숨음(`t < 0`) → 예고(`0 ≤ t < warn`) → 판정(한 번) → 번쩍임(0.28초) → 사라짐 | `Zone.t`, `Zone.hit`, `Zone.seek`(나타나기 전까지 플레이어를 따라감) |
| 플레이어 | 걷기 / 구르기 / 무적 | `player.dash`, `player.dashCd`, `player.safe` |
| 타격 멈춤 | 흐름 / 멈춤 | `game.stop` (0보다 크면 그 틱은 아무것도 진행하지 않는다. 내가 맞았을 때와 용이 쓰러질 때만 쓴다) |

게임 화면의 루프는 프레임마다 `step(game, 입력, dt)`을 한 번 부르고, `step`은 dt를 `STEP`(1/60초)을 넘지 않는 같은 길이의 틱으로 나눠 `update`를 돌린다. 남는 시간을 다음 프레임으로 넘기지 않아서 프레임과 틱이 어긋나 움직임이 떨리는 일이 없다. 카메라(`View`)는 플레이어를 한가운데에 두고, 용이 있으면 `pull`만큼, 시작 화면에서는 `lift`만큼 옮겨 본다.

게임 화면은 다른 애니메이션과 달리 `createTicker`를 쓰지 않는다. 움직임 줄이기가 켜져 있으면 `still`이 되어 게임을 할 수 없기 때문이고, 대신 탭이 가려지면 루프를 멈추고 움직임 줄이기에서는 화면 흔들림만 끈다. 홈 타일의 시연(`demo.ts`)은 아스키 무대에서 돌기 때문에 다른 장면처럼 티커를 따른다.

### 사진 변환기 (`src/features/convert/Converter.tsx`)

`empty`(사진 없음, 올리는 자리만 보인다) → `ready`(사진이 있고 글자 그림과 조절 항목이 보인다) 순서이고 되돌아가지 않는다. `ready`에서 다른 사진을 올리면 `ready`에 머문 채 그림만 바뀐다. 상태는 `source`가 있는지로 정해지고 `main`의 `data-state`에 적힌다. 열 수 없는 파일을 올렸을 때는 상태를 바꾸지 않고 안내 문구(`role="status"`)만 2.4초 동안 띄운다. 글자 그림은 `source`와 조절 값 넷(`cols`, `sharp`, `color`, `light`)으로만 정해지고 값이 바뀔 때마다 처음부터 다시 만든다.

### 한옥 골목 (`src/features/ink/alley/scene.ts`)

재생 상태는 다른 애니메이션처럼 `createTicker`를 따른다(`still`에서는 오후 3시 50분의 한 장면만 그린다). 장면 안의 상태는 아래와 같다.

| 상태 | 값 | 바뀌는 때 |
|---|---|---|
| 시각 `tau` | 0(자정)~1, 0.66에서 시작 | 180초에 한 바퀴 흐른다. 끄는 동안에는 흐르지 않고 끈 자리를 따른다 |
| 끌기 `dragging` | 없음 / `sun` / `moon` | 해나 달을 누르면 잡고, 손을 떼거나 취소되면 놓는다 |
| 사람 | 걷는 중 → 인사(숙임 0.5초, 멈춤, 폄 0.6초) → 걷는 중 | 누르면 인사한다. 인사하는 동안 다시 눌러도 처음부터 다시 하지 않는다(`bowing()`) |
| 감 | 달림 → 떨어지는 중 → 바닥에서 사라짐 → 24초 뒤 다시 달림 | 감나무를 누르면 하나가 떨어진다. 떨어지는 감이 있으면 더 떨어지지 않는다 |
| 고양이 | 잠 ↔ 깸(2.6초) | 누르면 깬다 |
| 안내 문구 | 보임 → 사라짐 (되돌아가지 않는다) | 장면 어디든 처음 누를 때 |

초롱, 풍경, 나무의 흔들림은 진자(`pendulum`)의 각도와 속도가 상태이고, 바람과 누름이 힘으로 들어간다. 지금 때(`밤`/`새벽`/`아침`/`낮`/`저녁`)는 svg의 `data-period`에, 사람 수는 `data-walkers`에 적힌다.

### 경로

`/` ↔ `/fire`, `/` ↔ `/ascii` ↔ `/ascii/<slug>`, `/` ↔ `/game`, `/` ↔ `/convert`, `/` ↔ `/alley`. 모든 화면에 돌아가는 길이 있다(불꽃놀이와 게임, 한옥 골목의 "홈" 버튼, 아스키 작품의 "아스키 목록" 버튼, 그 밖은 상단 내비게이션).

## 그대로 둔 것

`src/features/fire/knitFireEngine.ts`는 다른 프로젝트에서 옮겨 온 2,100줄짜리 엔진이고 자동 테스트가 없다. 안의 상태머신을 열거형으로 다시 짜면 원본과 벌어져서 원본의 수정 사항을 가져오기 어려워지므로, 구조는 두고 어떤 변수가 상태인지만 적는다.

| 상태머신 | 상태 | 상태를 담은 변수 |
|---|---|---|
| 엔진 수명 | 시작 전 → 도는 중 → 정리됨 | `raf`, `destroyed` |
| 자동 발사 | 쏘는 중 / 쉬는 중 / 꺼짐 | `nextAuto`, `quietUntil`, `S.amount`, `document.hidden` |
| 화면 청소 | 평소 → 차례가 됨(자동 발사 멈춤) → 비움 | `cleanAt`(-1이면 평소), `lastClean`, `launchCount` |
| 글자 발사 간격 | 쏠 수 있음 / 0.25초 대기 | `lastLaunch` |
| 누르고 있기 | 뗌 → 누름 → 0.32초 뒤 연발 | `hold`(null이면 뗌), `holdTimer` |
| 소리 | 없음 → 만들어짐 → 재생 가능 | `AC`, `AC.state`, `S.sound` |
| 입자 | `free` / `fly`(날아감 → 머무름 → 풀림) / `gather` | `Part.mode`, `age`·`dur`·`hold` |
| 한글 조합 중 엔터 | 조합 중이면 30ms 뒤에 쏜다 | `e.isComposing` |

엔진에서 바꾼 것은 한 가지다. 전에는 로고 이미지가 로드되거나 실패해야 시작했기 때문에 응답이 오지 않으면 화면이 빈 채로 멈췄다. 지금은 기다리지 않고 시작하고, 로고가 준비되기 전의 로고 불꽃은 하트로 대신한다(이 대체 동작은 원래 있던 것이다).

설정값(실, 하늘, 불꽃 양, 소리)은 엔진의 `S`, React의 `settings`, `localStorage` 세 곳에 있고 `FirePage`의 핸들러가 엔진과 React를 같이 고쳐서 맞춘다. 설정 항목을 늘릴 때는 세 곳을 모두 고쳐야 한다.

아스키 장면 안의 입자(불꽃 탄, 불티, 붓 자국, 별똥별)는 `life`가 0이 되면 사라지거나 다시 시작하는 단순한 수명 주기라서 따로 이름을 붙이지 않았다.
